# 동적 계약과 변경 영향 추적

## When to Use

- 공유 기능·데이터 형식·스케줄링·수명주기 변경의 소비자 영향을 판단할 때.
- 읽기 전용 영향 검토는 설명과 근거가 산출물이며 소비자 포팅 권한을 부여하지 않는다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 현재 diff·수정 예정 심볼·기대 계약을 확인하고 영향 질문을 `누가 무엇을 계속 기대하는가`로 정한다.
2. 기존 코드 그래프가 있으면 재사용하되 `search_files`와 `read_file`로 실제 원본의 관련 호출자를 모두 대조한다. 그래프가 없어도 원본 검색으로 계속한다.
3. 직접 호출 밖의 JSON 필드·DB schema·wire format·파일명·CLI 옵션·설정·feature flag·문서화된 계약을 찾는다.
4. 동적 등록·문자열 lookup·reflection·플러그인·다른 언어 소비자·저장된 과거 레코드 등 정적 그래프가 놓치는 연결을 확인한다.
5. 생성/시작/재시도/취소/재시작/teardown에서 소유자와 호출 순서가 달라지는지 추적하고 의존성 실제 버전도 확인한다.
6. 영향 목록을 소비자/계약/근거/변경 필요/미확인으로 정리한다. 안전 결론을 좌우하는 핵심 사실에 직접 실행·계약 검사를 집중한다.
7. 승인된 변경이면 해당 소비자 경로를 비례적으로 검증한다. 범위 밖 포팅·파괴적 마이그레이션은 실행 대신 영향과 선택지를 보고한다.
8. `안전 확인`, `조건부`, `미확인`을 나누어 결론을 내리고 현재 경로만 확인한 결과를 전체 호환성 보장으로 확대하지 않는다.

## 판단 예시

- 함수 인자를 바꾸지 않아도 JSON 키 삭제는 외부 소비자를 깨뜨릴 수 있다.
- 초기화 경로에서만 성공하는 변경은 재시작·취소 후 정리 경로가 안전하다는 증거가 아니다.

## Pitfalls

- 심볼 검색 0건을 외부 소비자 부재의 증거로 단정하지 않는다. 공개 계약과 동적 소비자를 별도로 본다.
- 잠재 영향이 있다는 이유로 전체 제품 재설계나 모든 과거 이력 조회를 강제하지 않는다.
- 타입 검사 통과는 직렬화 형식·수명주기·다른 언어 소비자 보존을 단독 증명하지 않는다.

## Verification

- 결론에 필요한 관련 호출자와 비코드 계약이 빠짐없이 검토됐는지 실제 원본과 목록을 대조한다.
- 안전성 핵심 주장에 실제 근거가 있는지 확인하고 미접근 외부 소비자는 미확인으로 남긴다.
- 검증은 현재 diff·환경·계약에 묶고 변경 후 다른 head에도 자동 유효하다고 하지 않는다.
