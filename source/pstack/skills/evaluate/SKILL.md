# 익명 출력 기반 효과 평가

## When to Use

- 사용자가 Prompt·스킬·구현 대안의 효과를 실제로 비교해 달라고 요청한 경우.
- 모든 일반 작업의 선행 평가로 쓰지 않으며 현재 호출 권한·비용·자료 범위 안에서 규모를 맞춘다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 평가할 질문과 성공/실패 기준을 먼저 고정한다. 정확성·범위 준수·행동 결과·비용 중 실제 결정에 필요한 축만 고른다.
2. 같은 난이도·입력·도구 조건의 사례를 정하고 치명적 실패 기준과 가중치·동률 처리 방식을 후보 결과를 보기 전에 정한다.
3. 기존 사례·평가기를 먼저 재사용한다. 새 외부 서비스·계정·모델 호출이 필요하면 가용성과 승인된 예산을 확인하고 임의 설치·전송하지 않는다.
4. 후보를 의미 없는 ID로 익명화하고 과제와 정답/채점 정보를 분리한다. 후보에게 평가 답·다른 후보 출력·실험 의도를 누출하지 않는다.
5. 같은 과제·환경·자원 한도에서 실제 후보 출력을 확보한다. 실제 생성·읽은 파일·행동 결과를 보며 자기보고 점수는 근거로 쓰지 않는다.
6. 평가자는 후보 정체·선호를 모르는 상태에서 고정 기준으로 판정한다. 현재 가능한 단독 평가도 허용하고 독립 모델 사용 여부를 정확히 표시한다.
7. 점수·치명 실패·기준별 근거·소요 비용·누락/중단을 집계한다. 표본·분산에 비해 작은 차이는 우위 불명확으로 남긴다.
8. 결과를 검토한 뒤 익명 ID를 해제하고 현재 과제에 대한 채택/보류와 한계를 보고한다. 승리 후보도 배포·설정 변경은 별도 승인 범위에 따른다.

## 판단 예시

- 안전 경계를 넘긴 후보는 빠르고 문장이 좋아도 사전 치명 실패 기준에 따라 탈락시킬 수 있다.
- 한 과제에서의 우위는 모든 프로젝트 생산성 향상의 증명이 아니다.

## Pitfalls

- 보기 좋은 설명을 실제 정확성·행동 결과보다 높게 평가하지 않는다. 정답·채점 기준 누출은 비교를 무효화할 수 있다.
- 같은 모델이 여러 역할을 맡은 결과를 블라인드·독립 모델 평가라고 과장하지 않는다.
- 평가 도중 기준을 바꿨다면 변경과 재채점 범위를 공개한다. 중단 후보를 누락하거나 성공으로 집계하지 않는다.

## Verification

- 동일 과제·조건, 사전 기준, 익명 대응표와 실제 출력·채점 근거가 일치하는지 확인한다.
- 계산·집계는 `terminal` 등으로 수행하고 성공/실패/미실행/누락 수를 원자료와 대조한다.
- 관측된 개선과 일반화 가능성을 분리한다. 후보를 실행하지 못했다면 비교 결과를 만들어내지 않는다.
