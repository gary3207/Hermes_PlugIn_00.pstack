# 독자 목적에 맞춘 기술 설명

## When to Use

- 코드 동작·이유·사용법을 설명하거나 한국어 입문 안내·기술 보고서를 작성할 때.
- 설명만 요청됐다면 명령 예시를 실제 실행·제품 변경의 승인으로 해석하지 않는다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 독자의 질문과 수준을 확인한다. 학습/tutorial, 작업/how-to, 조회/reference, 원리/explanation 중 현재 목적을 고르되 파일 분할을 강제하지 않는다.
2. 최소 완결 답을 먼저 정한다. 지금 알아야 할 결과와 이유를 쉬운 한국어 등 사용자의 언어로 말하고 정확한 기술 식별자는 그대로 둔다.
3. 실제 동작 질문은 `read_file`·`search_files`로 관련 입력→처리→출력 흐름·소유권·경계를 확인한다. 의도는 별도 명시 근거와 구분한다.
4. 조작 안내라면 위험·조건·대상을 동작 전에 적고 현재 환경에서 유효한 명령·경로·기대 결과·실패 시 다음 확인을 짝지어 쓴다.
5. 전문용어는 처음 등장할 때 짧게 풀고 같은 개념은 같은 이름을 쓴다. 비유는 실제 구현과 다른 한계를 함께 설명한다.
6. 그림·표·단계 예시는 이해를 돕는 경우에만 추가한다. 실제 UI 증거와 설명용 도식을 구분하고 정해진 그림 수·영어 문체를 강제하지 않는다.
7. 군더더기 수식·아첨·근거 없는 결론을 줄이되 경고·불확실성·명령·인용·필수 수치를 보존한다. 요청된 형식과 기존 문서 관례를 우선한다.
8. 독자가 다음에 할 행동이나 답의 한계를 짧게 마무리한다. 프롬프트 개선 요청이라면 범위·예산·산출물을 유지한 개선문만 주고 추가 구현은 하지 않는다.

## 판단 예시

- `CAS`는 `읽었던 값이 그대로일 때만 바꾸는 조건부 쓰기`로 풀고 실제 충돌 처리도 설명한다.
- 학습자가 원리를 물었으면 설치 명령부터 늘리지 않고 입력과 결과를 연결하는 작은 예부터 준다.

## Pitfalls

- 쉬운 설명이라는 이유로 정확한 경로·실패 조건·필수 수치를 삭제하거나 가설을 확정 사실로 바꾸지 않는다.
- 모든 요청을 다시 말하고 승인 대기를 만들지 않는다. 실제 목적 모호함이 있을 때만 짧게 확인한다.
- 영어 전용·금지 문장부호·고정 문장 수·도식 수 규칙을 한국어 설명에 강요하지 않는다.

## Verification

- 독자가 답만으로 질문의 핵심·조건·다음 행동을 이해할 수 있는지 목적에 맞춰 읽어본다.
- 명령·식별자·출처와 관측 사실을 실제 자료에 대조한다. 실행하지 않은 예시 출력은 예상 또는 예시라고 표시한다.
- 설명 대상 밖 구현·설치·외부 쓰기를 하지 않았는지 확인하고 실행 검증 여부를 정확히 구분한다.
