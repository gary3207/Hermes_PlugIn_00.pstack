# 독립 작업 분할과 근거 기반 대안 선택

## When to Use

- 사용자가 대안을 비교하거나 전수 범위를 독립 단위로 나누도록 요청한 경우.
- 순차로 더 싼 작은 일에는 직접 처리하고 고정 작업자·다중 모델·클라우드 실행을 요구하지 않는다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. partition은 범위 합집합을 완성하는 분할, race는 같은 과제의 후보 중 선택이라는 차이를 정한다. 비교할 결정이 없다면 후보 구현을 만들지 않는다.
2. 완료 조건·평가 기준·예산/시간 한도·허용 자료·통합 주체를 고정한다. 후보 수는 실제 이익·가용 도구에 맞추며 정해진 수를 강제하지 않는다.
3. 각 brief에 목표, 정확한 입력/대상 버전, 담당 경로, 금지 행동, 검증법, 출력 위치, 보고 형식을 넣는다. 코드 비교는 실제 SHA·diff를 명시하고 단순 문서 질문에 불필요한 SHA를 요구하지 않는다.
4. partition은 겹침·누락을 확인하고 공유 산출물의 단일 writer를 둔다. race는 동일 과제·조건과 독립 출력 위치를 주며 후보끼리 결과를 섞지 않는다.
5. 필요하고 사용 가능할 때 `delegate_task` 등 기존 위임 수단을 쓴다. 유지 후보는 `source/`, 일시 후보는 승인된 관리형 scratch 등으로 격리한다.
6. 실제 출력·검증 결과를 수집하고 실패·중단·누락을 별도 집계한다. 자가 평가·heartbeat를 행동 검증으로 세지 않는다.
7. partition은 요구된 전체 집합과 수집 집합을 프로그램으로 대조한다. race는 사전 기준으로 기준안 하나를 고르고 탈락 사유·실측 근거를 기록한다.
8. 다른 후보의 장점은 근거를 확인해 필요한 부분만 수동 통합하고 통합 결과를 다시 검사한다. 범위 밖 구현·설치·원격 변경은 자동 수행하지 않는다.

## 판단 예시

- 16개 문서 분할이라면 16개 고유 ID가 실제 산출물에 있는지 집합으로 확인한다.
- 세 설계 경쟁을 요청받았어도 모두 자동 채택하지 않고 기준안 하나와 검증된 작은 장점만 고른다.

## Pitfalls

- 같은 브랜치·파일에 여러 작성자가 쓰게 하거나 worktree 분리가 push·reset 허가라고 해석하지 않는다.
- 개인정보·내부 코드·원문 기록을 승인 없이 새 외부환경·모델로 보내지 않는다. 기본 클라우드 가정을 두지 않는다.
- 후보 dropout·미검증 gap을 pass로 집계하거나 모든 후보를 억지로 합쳐 새 검증되지 않은 설계를 만들지 않는다.

## Verification

- partition은 기대 ID와 실제 고유 ID의 누락·중복을 확인하고 race는 동일 조건·선택 기준·결과 근거를 대조한다.
- 위임 결과의 파일·실제 실행 출력을 직접 확인하고 단독/동일 모델/다른 모델 여부와 한계를 정확히 표시한다.
- 통합된 현재 변경을 검사한다. 후보 하나의 통과를 통합본·다른 환경의 통과로 옮기지 않는다.
