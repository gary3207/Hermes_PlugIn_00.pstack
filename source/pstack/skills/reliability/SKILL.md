# 재시도 수렴과 공유 쓰기 보장

## When to Use

- 중복 실행·부분 실패·재시작·취소·공유 상태 경합의 설계나 승인된 수정을 할 때.
- 단순 읽기 작업에 잠금·새 저장소·추가 실행 관리기를 먼저 만들지 않는다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 실제 상태 변경 단위를 찾는다. 현재/목표 상태, 안정된 리소스 ID, 성공 결과와 실패 결과의 저장 위치를 확인한다.
2. 재시도 시 현재 상태를 읽고 목표와의 차이만 적용하도록 설계한다. 표시 제목 대신 업무 ID·요청 ID 등 실제 중복 의미에 맞는 키를 사용한다.
3. 커밋 전후 중단·응답 유실·취소 직후 재실행을 생각하고 `이미 성공했으나 응답만 잃음`을 실패와 구분한다. 성공 산출물을 무조건 폐기하지 않는다.
4. 실제 쓰기 주체와 공유 객체를 목록화한다. 독립 산출물은 먼저 분리하고 진짜 공유 객체만 기존 단일 writer·transaction·lock·CAS로 보호한다.
5. 읽기-판정-쓰기 구간과 외부 부수 효과의 원자성 경계를 정한다. 잠금의 소유자·범위·만료·복구와 재시도 시 충돌 응답 처리를 확인한다.
6. `terminal` 등 기존 실행 경로로 대표 중복·중단·경합 사례를 격리된 대상에서 확인한다. 실제 외부 쓰기는 승인된 정확한 대상에서만 실행한다.
7. 취소가 새 작업 수락을 막는 것인지 진행 중 쓰기까지 멈추는 것인지 구분한다. 기존 writer가 끝났거나 격리된 근거 없이 새 writer를 시작하지 않는다.
8. 외부 쓰기는 저장된 실제 대상을 읽어 수렴·중복 방지·성공 결과 보존을 확인한다. 아직 남은 위험과 보장하지 못하는 경계를 명시한다.

## 판단 예시

- 파일별 독립 결과는 각자 쓰고 최종 집계만 한 writer가 담당할 수 있다.
- 원격 생성 성공 후 timeout이라면 재생성 전에 안정된 ID로 기존 리소스를 조회한다.

## Pitfalls

- `동시에 쓰지 말자`는 지침은 잠금이 아니다. 단일 프로세스 lock도 다른 프로세스·원격 writer를 막는다고 단정하지 않는다.
- 임의 TTL·stale 판단으로 사용자 파일·실행 중 작업을 삭제하거나 소유권을 빼앗지 않는다.
- 멱등성 키만 추가해 모든 외부 효과가 exactly-once가 됐다고 하지 않는다. 지원되지 않는 원자성은 한계로 남긴다.

## Verification

- 같은 요청 반복 후 추가 부수 효과·성공 산출물 손실이 없는지, 대표 중단 후 목표 상태로 재개되는지 확인한다.
- 동시 writer 실험에서 공유 불변식이 보존되는지 실행 증거를 확인한다. 새 프레임워크 없이 기존 검사를 우선한다.
- 자기 소유 실험 자원만 승인된 방식으로 정리하고 실패 흔적·필요 증거는 보존한다.
