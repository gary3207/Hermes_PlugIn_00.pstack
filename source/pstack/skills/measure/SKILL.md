# 실작업 성능 측정과 공정 비교

## When to Use

- 실제 성능 불만·전후 개선·처리량 비교를 측정하거나 관측 수치를 보고할 때.
- 단순 ballpark 요청에는 한 번 측정도 허용하며 정밀 개선 주장과 구별한다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 수치가 뜻할 실제 작업·단위·관측 범위와 사용자의 질문을 정한다. 대략값인지 비교 우위인지 인과 설명인지 구분한다.
2. 입력 크기·동시성·버전·하드웨어·캐시·워밍업·정확성 조건을 기록하고 현실 workload를 기존 도구로 실행한다.
3. 시작/끝 경계 안에 실제 작업이 들어가는지 확인한다. 지연 실행·백그라운드 처리·오류 응답·미실행을 빠른 성공으로 세지 않는다.
4. 성공·오류·timeout·누락 수와 실제 작업량을 함께 집계한다. 부하 발생기 포화·다른 작업 간섭·단위/물리 한계도 필요한 만큼 확인한다.
5. 비교라면 조건을 맞춰 순서를 교차하고 주장 강도에 맞는 반복·중앙값·분산·꼬리 지연을 낸다. 단순 대략값은 한 번임을 표시한다.
6. 계산은 `terminal` 등 도구로 수행한다. 개선 비율은 같은 분모·업무를 쓰고 microbenchmark 차이와 end-to-end 기여를 구분한다.
7. 원인 개선이 승인됐다면 불필요 작업 제거→중복 제거→빈도 감소→지연 처리→동시성→작업 단가 축소 중 관측 근거가 있는 최소 변경을 하나씩 시험한다.
8. 정확성·오류율·회귀 조건을 보존하고 노이즈·예산 대비 충분한 답이 나오면 종료한다. 관측 차이와 미확인 원인을 따로 보고한다.

## 판단 예시

- API가 500으로 빨리 끝난 경우 그 시간은 오류 지연이며 성공 처리량과 합치지 않는다.
- `대략 2초인가`라는 질문에는 오류 없는 실제 1회 관측과 1회 한계로 충분할 수 있다.

## Pitfalls

- 빠른 실패·빈 결과·작업 생략은 성능 개선이 아니다. 오류율을 숨긴 평균만 발표하지 않는다.
- 관측 시간 보고 자체에 완전한 병목 증명·새 benchmark 인프라·최소 시도 횟수를 강제하지 않는다.
- 공정 조건을 만들겠다며 사용자 프로세스를 임의 종료하거나 실제 운영 부하를 승인 없이 발생시키지 않는다.

## Verification

- 명령·버전·입력·측정 구간·단위·오류/작업량·표본 수가 실제 출력에 연결되는지 확인한다.
- 전후 결과가 같은 일을 하는지 검사하고 baseline 변경·누락 표본·환경 차이와 불확실성을 명시한다.
- 개선을 적용했다면 관련 행동 검사도 실행한다. 값만 측정했다면 원인·채택·전체 서비스 개선을 보장하지 않는다.
