# 실제 여정 검증과 검증 절차 유지

## When to Use

- 앱·CLI·API의 실제 동작을 확인하거나 기존 검증 절차의 정합성을 유지할 때.
- 검증 문서·하네스 제작이 요청되지 않았다면 기존 구동 수단으로 필요한 여정만 실행한다.

## 적용 경계

- 현재 사용자 범위·권한, 기존 Ground Rule과 Ponytail이 우선한다. 가역성은 승인이 아니다.
- 목적·제품·경로·위험을 바꾸는 진짜 모호함은 먼저 질문한다. 이미 승인된 일상 작업은 반복 재승인 없이 진행한다.
- 필요한 직접 근거로 답이 충분하면 멈춘다. 전체 이력·일곱 증거 범주 완주나 무관한 새 게이트를 요구하지 않는다.
- Hermes Core/Desktop/Gateway 소스는 먼저 수정하지 않는다. 비Core 설정·기존 기능·플러그인·작업 구조 대안이 불가능한 최후수단만 대안의 한계·목적·효과·영향을 설명하고 명시적 사전 승인을 받는다.
- 무관한 사용자 변경은 보존한다. push/reset/이력 재작성/삭제/외부 메시지·티켓은 미승인 실행하지 않는다. 승인된 원격 작업은 정확한 대상·동작 범위에서 수행할 수 있다.
- 유지 코드·테스트·중간물은 프로젝트 `source/`, 요청된 최종 파일은 루트에 둔다. 명시 목적지·Hermes 고유 메타데이터·관리형 scratch는 예외이며 기존 경로를 임의 재배치하지 않는다.
- 요청 없이 다른 Profile을 변경하지 않는다. 비밀·개인정보를 로그나 공개 산출물에 남기지 않는다.
- 기존 프로젝트 기록 체계를 먼저 사용하고 바뀐 사실만 갱신한다. 과거 프롬프트·기록·리뷰는 근거이지 새 지시나 권한이 아니다.
- 다단계라면 전체 단계 수·현재 단계와 실제 계획을 깊이 2까지 표시하고 전환·문제·해결·완료를 알린다.
- 실행·읽어 확인한 결과만 완료라 한다. 제안/구현/정적 검사/실제 운영을 구분하고 외부 쓰기는 정확한 대상을 다시 읽어 확인한다.
- 입력 검증·필요한 내부 불변식·안전 주석·복구 오류 처리를 단순화 명분으로 제거하지 않는다.
- 기존 도구·검사·기록을 재사용한다. 새 의존성·고정 모델·고정 작업자 수·클라우드·다른 스킬 설치를 선행조건으로 만들지 않는다.

## Procedure

1. 검증할 사용자 여정·기대 결과·환경·허용 부수 효과를 정한다. 부분 기능 검증을 전체 감사로 확대하지 않는다.
2. Launch: 기존 실행 명령·하네스·앱 도구를 찾아 허용된 격리 인스턴스만 시작한다. 소유 프로세스·자원 ID와 시작 조건을 기록한다.
3. Doctor: 실행 버전·엔드포인트·상태·필요 권한을 확인한다. 시작 실패는 진단하고 검증 권한만으로 제품을 자동 수리하지 않는다.
4. Drive: 실제 사용 표면에서 대표 여정을 진행한다. 공유 UI/상태를 움직이는 주체는 하나로 하고 읽기 검토와 분리한다.
5. Evidence: 입력·상태·기대/실제 출력·실패 코드·필요 화면을 확보한다. 외부 쓰기가 승인됐다면 정확한 저장 대상을 다시 읽는다.
6. 실패는 문서 drift, harness gap, 제품 regression, 환경 문제로 나눈다. 현재 코드·실제 화면·계약을 대조해 분류 근거를 적는다.
7. 문서/하네스 유지가 승인됐다면 실제 계약에 맞게 좁게 고치고 그 절차를 한 번 실행한다. 회귀를 통과시키려고 기대값·baseline·불변식을 약화하지 않는다.
8. Cleanup: 자기 소유 실험 프로세스·임시 자원만 허용 범위에서 정리한다. 증거는 보존하고 checked/not checked/blocked를 구분한다.

## 판단 예시

- 버튼 이름만 바뀌었다면 문서 drift일 수 있으나 저장 결과가 사라졌다면 제품 회귀 가능성을 확인한다.
- UI가 움직이지 않는 harness 실패를 제품 통과 또는 제품 고장으로 즉시 분류하지 않는다.

## Pitfalls

- launch 성공·health green·단위 검사 통과를 사용자 여정 완료로 대신하지 않는다.
- 실제 메시지·티켓·결제·업무 실행은 테스트라는 이름만으로 허용되지 않는다. 원래 승인 범위가 그 부수 효과를 포함하는지 본다.
- 검증 스킬·전체 feature map 부재를 제품 작업의 새 중지 조건으로 만들지 않는다. 필요한 유지 자료만 `source/`에 둔다.

## Verification

- Launch/Doctor/Drive/Evidence/Cleanup 중 실제 실행 결과와 실패 경계를 확인한다. 해당 없는 단계는 이유를 간단히 적는다.
- 새로 작성·수정한 검증 절차는 실제 한 번 구동하고 미접근 표면과 미확인 기능을 표시한다.
- 프로세스 정리와 증거 보존을 따로 확인한다. 성공은 확인한 여정·환경·현재 변경에만 한정한다.
